# 同一任务的累计记录接续

## 范围与检查点

#151 已于 2026-10-27 合入主分支（`28f9d3a`）。本轮处理 #130 的工具请求、
控制结果和 turn 观察记录：同一个任务、上游会话及原队列可以持续跨越旧的累计
64 条限制。检查点在任务自己的 runtime 内，不另建任务、不追加无限历史文件。

`broker-turn.json` 记录宿主收到的 `turn/start` 成功响应，或既有原生 TUI 入口接受的
本接收端 `turn/started` 事件。它在处理随后的工具请求前落盘；执行入口同时验证
原接收端当前 turn。旧 turn 的请求不能因为其历史记录已回收而再次执行。
当前 turn 的请求仍保留精确请求与结果，用于拒绝 ID 改写及重复回复。

只有满足以下条件的一对记录才会回收：

- turn 已明确 `completed`，且不是当前 turn。
- 控制记录为 `complete`、broker 记录为 `responded`，请求及结果逐字对应。
- `run` 已收集为 `signalled`，队列中同一 wait、精确 binding 的结果已被 apply。
- `deliver` 已成功返回。失败的外部操作可能已部分执行，继续保留。
- `finalize` 始终保留，直至既有终结提交与统一回收消费它。

`executing`、`sending`、待回复、请求／结果不一致、失败／中断／未知 turn，以及尚未
应用的 worker 结果都不会被检查点删除。没有可证明的消费记录时继续保留。
已完成的旧 turn 事件也只有在工具、worker、当前 turn 和待处理请求都不再引用时才回收；
最近一次 turn 事件保留用于观察。审批／用户输入记录仅在上游给出同一 thread、同一
request ID 的 `serverRequest/resolved` 后移除，Flow 不替用户作答。

## 中断与并发

broker 是检查点的唯一执行者。它以非阻塞方式取得既有 `control-service.lock`，
与队列控制执行及 worker 收集互斥；拿不到锁就留待后续观察周期。

删除之前保存 `record-checkpoint.json`，其中包含本次待删除键和每条原内容的 SHA-256。
broker 在改写任何文件前检查全部剩余内容，再依次替换控制、工具、事件记录。
中断后重启 broker 只完成这份清单：已删除的键允许缺省，仍存在的键必须匹配；
整个文件丢失或内容改变会保留现场并报错。检查点准备期间，控制执行和恢复安全检查
不能把部分删除误判为“没有未决操作”。完成后清单缩为当前 generation、turn 与计数，
不累加历史，也不重发模型 turn、工具回复、Git 操作或业务动作。

原 `receiver-start.json`、任务 instance、会话和队列身份不改写。上述文件均位于原任务
runtime 内，随既有终态清理删除。

## 容量与验证边界

工具／控制记录仍各限 64 条、实际落盘 JSON 各限 1 MiB；turn 与 pending 观察各限
64 条，事件文件限 16 MiB。这里保留的是当前 turn 和尚有引用的工作窗口。
一个未结束 turn 内累积 64 次调用、过多未决操作或单条过大的结果仍会触发容量保护；
这轮没有增加自动中断／轮转模型 turn 的协议。

容量拒绝保留既有记录，并写入 `record-capacity.json` 的具体文件、计数、字节上限和
原任务检查指引。它是观察／恢复阻塞，不是业务失败终态，也不允许重放未知操作。
超限导致传输退出时，独立观察器将该记录和 broker 错误一起交给恢复入口；操作方需先
检查并完成或协调原 turn、未决操作，再在同一任务中接续。不会仅凭容量记录自动恢复发送。
`herdr_queue inspect` 可见当前检查点与最近一次容量阻塞证据。

定向协议验收：同一个真实 broker／watcher、同一任务和会话完成 **71 个 turn、75 次工具
请求**（含最后重放的一条旧 apply），旧 apply 返回拒绝，任务版本未再次推进，最终
完整回收任务目录和登记；共享协议服务、配置文件及另一会话保持可用。首轮 **15.66 秒通过**。
该用例使用协议夹具，不声明新增真实模型／Herdr 验收。

单元回归另覆盖 100 个 turn／200 次调用（结果累计超过 1 MiB、磁盘窗口保持有界）、
一次 drain 超过 64 个完成 turn、每个文件改写前缀的中断恢复、锁竞争、内容改变拒绝、
未知外部操作、精确 worker binding 应用、审批解析和容量保护。
独立 broker 进程还验证从各个部分落盘状态重启完成检查点，全程不建立上游连接。

首轮完整回归暴露了两处并发问题：空闲 broker 不应因检查点探测取得生命周期许可；
正常的控制服务锁竞争不应结束队列 watcher。两处均已修正，空闲终结与开发→评审→
本地交付的定向复验通过；后者复验用时 25.16 秒。协议夹具另显式持有服务锁，验证
队列 tick 等待后续周期而不退出。

本轮不处理队列业务历史、阶段资源归档、发布角色、人工写入权交接或 ClaudeCode adapter。
这些仍由后续 issue 增量覆盖。

本地完整 all-targets 覆盖率回归通过。随后函数拆分和观察证据补充经 task_runtime 模块
**89 项通过、2 项显式忽略**，及恢复持锁协议复验 **21.52 秒通过**。CRAP 绝对阈值 10、
无 baseline，**6210 个函数零违规**；fmt、lint-policy、全 targets/features Clippy 与
release 构建通过。真实模型／Herdr 证据仍沿用已合入 #151 的范围；本轮新增的是协议与
检查点验收，最终提交的远端门禁由对应 PR 跟踪。
